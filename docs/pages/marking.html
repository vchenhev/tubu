入口与工作概览

进入“检测 → 打标设置”，打开独立弹窗。默认显示“工作概览”，查看当前料号已配置的区域数量、打标机数量、各机软件待发与写入结果，以及执行个数、实际打标个数、漏标个数和报警反馈。参数编辑与设备操作集中在该弹窗中。

本章配图中的料号、名称、地址、数值和连接状态仅供阅读参考，不作为真实设备运行证据。

“软件写入成功”只表示本次位置写入返回成功，不代表打标机已完成动作。实际数和漏标数来自当前选择的PLC或485反馈来源。PLC反馈地址未填写显示“未配置”；读取失败或型号未提供的统计不视作零，未完整读取时汇总显示“—”。

配置打标机和基础点位

  1. 切换到第二页“参数配置 → 打标机与PLC点位”，点击“新增打标机”，填写名称并选择是否启用。在名称后面的“站号”列逐台填写该设备的485站号；同一型号的不同设备也分别设置。站号范围为1至247，同一485总线上启用设备的站号不能重复，保存后生效。
  2. 填写每台打标机自己的“打标脉冲（写）”地址。连接复用当前软件的系统控制器，不在此页面设置PLC协议、IP或端口。
  3. 使用PLC反馈时，按需要填写报警、执行数、实际数和漏标数读取地址。留空的反馈地址不读取，不妨碍已完整配置的位置打标；选择485反馈后，这四类PLC地址保留但不参与读取。
  4. 反馈地址可使用“地址|float”“地址|int”“地址|uint”或“地址|bool”；未指定类型时按float读取。类型必须与PLC实际定义一致。打标位置输出固定为Float32，地址栏直接填写写入地址。

不同打标机使用不同的打标脉冲写入地址。“移除选中打标机”同时移除草稿中的相关绑定及距离关系，保存前不影响运行配置。

绑定ROI和相机距离

  1. 进入“ROI绑定与距离”，在对应ROI行的“绑定打标机（可多选）”列展开下拉框，勾选需要关联的打标机，可选择多台；取消全部勾选可清空该ROI的绑定。关闭下拉框后更新草稿，保存配置后才影响运行。
  2. 启用需要参与打标的ROI。关联的检测ROI及打标机也须处于启用状态。
  3. 直接在右侧距离表中填写各“相机＋打标机”的走料距离，单位mm，按极片从相机检测线到实际打标点经过的路径长度填写。每一对相机和打标机共用一项距离，同一台打标机对应不同相机时分别设置；未填写距离不能开启打标。

同一瑕疵的范围跨过多个ROI时，全部相交区域参与NG打标判定；仅贴住边界不额外命中邻区，点状结果在分界处归入右侧或下侧的半开区间。同一瑕疵通过多个ROI命中同一台打标机时，合并为一条任务，只发送一次，日志保留全部命中ROI和绑定来源。不同瑕疵保持独立，间隔屏蔽另按配置处理。

ROI绑定与距离两张表格会随弹窗的可用高度扩展，底部保留保存及重新读取按钮；记录超过可视范围时，在对应表格内滚动查看和编辑。

保存、启停与手动测试

点击“保存打标配置”后，参数经过校验并替换运行快照；“重新读取”放弃当前窗口未保存修改。配置按独立文件保存，ROI绑定随料号区分；料号切换后重新读取再编辑。配置文件损坏时停用打标并保留原文件，不能通过重新读取将损坏内容静默覆盖。

功能已开放并且“开启打标”处于开启状态时，正式运行中的有效NG结果才会生成位置任务。最终分类为OK的候选不参与打标。功能未开放或打标开关关闭后，软件停止新任务并取消本模块尚未发送的任务；已经下发到PLC的位置不通过本页面自动撤销。

在“打标控制”中配置偏移距离、间隔打标屏蔽及发送方式。偏移和屏蔽距离单位为mm；发送窗口单位为脉冲。关闭排序时按任务入队顺序发送；开启排序时在配置窗口内按目标脉冲顺序发送。已到达或超过的目标位置会拒发并记录原因。

在“打标控制 → 脉冲与发送参数”中填写“帧末脉冲地址（读）”和“编码器实时地址（读）”，保存后生效。两个地址仅供打标使用，PLC连接复用当前软件；保存打标地址不会修改系统原检测地址。地址可直接填写，默认按float读取，也可填写“地址|int”或“地址|uint”，类型须与PLC定义一致。检测打标优先使用每帧PLC实读的帧末脉冲；与原检测地址及类型相同并取得有效应答时，共用同一次读取。帧末脉冲读取失败后，在图像回调准备阶段立即读取编码器实时脉冲作为近似回退值，日志明确标记实际读取地址、近似来源及帧末失败原因。两种来源都无效时跳过本帧打标，不使用历史读数或图高累加位置替代。原检测的图高累加不受影响。地址保存后，软件未发任务和旧配置的在途帧失效，已经下发到PLC的位置不自动撤销。

连涂直接使用有效的基础脉冲作为帧尾脉冲。间涂拼图成功后，将拼图返回的剩余尾部行数LastPuzzleHeight按“剩余行数×图像纵向精度÷脉冲当量”换算成尾部修正脉冲，再从原始基础脉冲中扣减一次，作为本次打标的实际帧尾脉冲；200行显示边界不参与额外修正。尾部为0时不扣减；拼图未生成结果时等待后续帧，尾部行数、标定、当量或修正值无效时跳过打标并记录原因。

自动打标根据本帧确定的帧尾脉冲、图像纵向精度和瑕疵质心位置还原瑕疵绝对脉冲，再分别加上“走料距离÷脉冲当量”和“打标偏移÷脉冲当量”。图像精度单位为mm/像素，脉冲当量单位为mm/脉冲；所有补偿换算到脉冲后相加，最终统一取整并检查Float32能否无损表达。发送前只读取一次编码器实时脉冲，用于判断过期并记录发送时位置，不替换本帧帧尾脉冲，也不重新计算目标。

“一键打标”使用已保存的打标机地址和对应相机距离，从独立配置的编码器实时地址读取位置后计算测试目标。先保存未完成的编辑，再选择相机和打标机执行。手动测试同样受功能开关约束。

选择反馈来源与485设备控制

  1. 进入“参数配置 → 打标控制”，在“反馈方式与共享485总线”中选择“PLC 地址反馈”或“485 设备反馈”。该选择对全部打标机统一生效，不逐台混用。
  2. 选择485反馈时，从COM下拉框选择实际连接端口，选择总线波特率。“刷新串口”重新枚举本机端口，不连接设备；当前端口暂时离线时保留原配置文本，通信状态会提示失败。
  3. 在上方打标机选择框中选择设备，再从型号下拉框选择“胜之行”或“马斯特”。站号在“打标机与PLC点位”表格中、对应设备名称后的“站号”列填写；所有启用设备共用COM和波特率，各设备使用独立站号。
  4. 保存打标配置后，软件按保存参数连接485总线，打开窗口期间每10秒顺序读取一轮启用设备。前一轮未结束时不叠加轮询；单台设备失败后继续读取其他站号。

PLC模式不打开485串口，按已配置的PLC地址读取基础反馈；485模式不读取报警、执行数、实际数和漏标数PLC地址，设备型号及站号决定读取协议。两种模式的自动位置打标均继续使用原PLC打标写入地址，帧末脉冲、实时编码器和位置补偿也继续走PLC链路。

485型号统计与报警设备控制
胜之行状态报警、出标总数、成功数、漏标数。485打标测试、报警复位、漏标清零、总数清零。
马斯特位组合状态报警、出标总数、成功数；当前协议未提供漏标读取，显示“未提供”。报警复位、总数清零；485直接打标与漏标清零保持禁用。

485反馈中的“执行个数”显示设备出标总数，“实际个数”显示成功数；不支持的统计不通过差值或软件发送次数推算。马斯特漏标数未提供时，漏标汇总显示“—”。

“补充设备控制”只操作当前选中的一台设备，按钮按已确认的型号能力开放；点击前先保存参数。485打标测试直接向选中设备发送一次设备测试命令，需要打标功能已开启。上方“一键打标”仍是按相机距离和实时编码器计算目标的PLC位置测试，两者用途不同。参数下发和PLC清队列功能不提供。

轮询与控制共用串口锁，避免报文交叉；控制失败不自动重发。马斯特总数清零包含连续两步应答，第二步失败时日志注明首步已应答，不将部分成功误报为全部成功。统计在后续轮询中更新，不直接将界面计数置零。

读取失败时显示失败原因并保留上次有效统计；总数不把失败值当成零。连接异常后在下一轮尝试重连，配置切换时释放旧连接并停止后续旧请求。关闭打标设置窗口会停止485监视并释放串口，后台PLC位置任务继续按原状态运行。

日志与异常检查

日志以“【打标】”标识模块。“脉冲获取”记录相机、帧号、基础脉冲、实际读取地址、近似标记、位置来源及配置版本；帧末读取失败后的来源说明同时保留失败原因。“尾部修正”记录间涂原始基础脉冲、LastPuzzleHeight、纵向精度、脉冲当量、尾部修正量及修正后帧尾脉冲。

按任务编号关联“计算入队”“准备发送”“发送审计”“写入成功”“发送失败”“取消”“屏蔽”等阶段。“计算入队”记录原始基准、修正后帧尾、瑕疵绝对脉冲和补偿后的目标。“发送审计”在实际PLC写入前统一记录帧尾脉冲、发送脉冲、发送地址、发送时实时脉冲，并包含帧尾来源、实际读取地址、编码器地址、连涂/间涂模式、LastPuzzleHeight、尾部修正量、打标机编号和配置版本。该记录表示一次写入尝试，需结合后续“写入成功”或“发送失败”确认通信结果。其余任务记录保留卷号、相机、帧号、同步代次、瑕疵、命中ROI、绑定来源、距离、偏移、当量、Float32计算结果及耗时。

  1. 入口不可用时先确认功能是否已开放；进入窗口后确认模块开关及当前料号。
  2. 确认检测ROI、绑定设备、写入地址和相机距离完整，基础PLC连接正常。
  3. 出现“本帧没有可靠的PLC位置基准”时，检查打标配置中的帧末地址、编码器实时地址、两次读取应答和脉冲当量；不能只看界面上的历史读数。
  4. 出现“Float32无法无损表达目标整数脉冲”时，核对累计脉冲范围与PLC数据定义，不通过放宽检查继续发送。
  5. 遇到目标过期、间隔屏蔽或配置切换取消，按任务日志检查对应原因。写入失败或通信异常不会自动补发，避免结果不明时重复动作。
  6. PLC基础反馈按“【基础反馈变化】”检查；485反馈按“【485反馈】”检查设备编号、型号、COM、站号、状态和本次读数，控制按“【485控制】”核对动作、应答、耗时及失败原因。先核对全局来源，再查串口占用、总线波特率和重复站号；累计计数不能替代逐条执行确认，实际落标位置仍需在设备上核对。
